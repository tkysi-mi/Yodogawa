# VerifyIssueFacts

## 目的

- GitHub Issue の記述（主張・前提・参照ファイル）をコードベースの現状と照合し、各主張を【事実 / 誤り / 不明】に判定する。
- 各判定に `file_path:line` の証拠を必ず添える。
- Issue が触れていない関連箇所（呼び出し元・依存・連動箇所）を網羅し、影響範囲マップを提示する。
- Issue 対応に着手する前の「事実確認」を一度で済ませる。

## 制約（最重要）

<critical>
- このスキルは**読み取り専用**。`allowed-tools` に `Write`/`Edit`/`NotebookEdit` を含めず、Bash も読み取り専用コマンド（`gh issue/pr view`, `git log/blame/show/diff/grep`）にスコープしている。**コードもファイルも一切編集・作成しない。**
- 検証結果は**チャットに出力するのみ**。レポートをファイル保存しない。
- 「修正すべき」と判断しても、修正の実装・提案コードの記述はこのスキルの責務外。**事実の提示にとどめる**。
- 確証が持てない主張は無理に【事実】【誤り】に倒さず【不明】とし、何を確認すれば確定するかを書く（confident なバイアスを避ける）。
</critical>

## 手順

`$ARGUMENTS` に issue 番号または URL があればそれを対象にする。なければ手順1で確認する。

### 1. Issue の取得

```bash
gh issue view <番号> --comments
```

- 本文に加えコメントも取得し、議論で更新された前提も拾う。
- `$ARGUMENTS` 未指定なら、対象の issue 番号をユーザーに確認する。`gh` が使えない／本文が手元にしかない場合は本文の貼り付けを促す。
- Issue が PR を参照していれば `gh pr view <番号>` で関連差分の文脈を補う。

### 2. 主張の分解

Issue 本文・コメントを読み、**検証可能な命題（claim）** に分解して箇条書きにする。後で1つずつ判定する。

例:

- 「ファイル X の関数 Y が状態 Z を保存する」
- 「フィルタ A が効かない（no-op）」
- 「削除済み GID が保存／読込時に除外されていない」

主観・要望（「〜したい」「〜すべき」）はコードと照合できないので claim から除外し、別途「要望」として控える。

### 3. 各 claim のコード照合

claim ごとに該当コードを特定して実挙動を読み取る:

- 参照ファイル／シンボルは **Read** で開く。
- シンボル・文字列は **Grep**、ファイル探索は **Glob**。
- 経緯・いつ変わったかの確認が要るときのみ `git log -p <path>` / `git blame <path>` / `git show <sha>`。

判定を付ける:

| 判定 | 意味 |
|------|------|
| 事実 | コードが主張通りに書かれている／振る舞う |
| 誤り | コードは主張と異なる（実際の挙動を併記する） |
| 不明 | コードだけでは確定できない（動的確認・実行が必要、外部依存など） |

**各判定に必ず `file_path:line` の証拠を添える。** 証拠のない判定は出さない。

### 4. 関連箇所の網羅マップ

claim に登場したシンボル・エンドポイント・メタフィールドキー・定数について:

- **呼び出し元・参照箇所**を Grep で洗い出す。
- 同じ GID／キー／定数を使う**連動箇所**を探す。
- 「Issue は触れていないが、この変更で影響しうる箇所」を列挙する（影響範囲の取りこぼし防止）。

### 5. レポート出力（チャットのみ）

下記フォーマットでチャットに出力する。ファイルには書かない。

## 出力フォーマット

```
## Issue #<n> 事実確認レポート

### サマリ
<1-2文。主張は概ね正しい / 一部誤り / 不明点あり 等>

### 主張ごとの判定
| # | 主張 | 判定 | 証拠 | 備考 |
|---|------|------|------|------|
| 1 | ... | 事実 | path:line | ... |
| 2 | ... | 誤り | path:line | 実際は〜 |

### 関連箇所マップ（影響範囲）
- <symbol/key>: 参照元 path:line, path:line ...
- Issue 未言及だが関連: path:line — 理由

### 不明点 / 動的確認が必要な項目
- ...
```

## 完了条件

- すべての claim に判定と `file_path:line` 証拠がついている。
- 関連箇所マップが提示されている。
- **ファイル・コードの変更が一切ない**（読み取り専用を遵守）。
