# ヒアリング質問集

a-002 の各テンプレートに記入する際のヒアリング質問一覧。Product Brief を中核に、機能・ユーザーストーリーをカバーする。

末尾の「[深掘りフレーム集](#深掘りフレーム集product-brief--mvp-scope-共通)」は Product Brief（a-002）と MVP Scope（`/a-002a-slice-mvp-scope`）の両方で使える思考技法。表層の要望で止めず、根本課題・失敗要因・最小スコープまで掘り下げるために併用する。

## 手順3: Product Brief

`01-product-brief.md` の各節を埋めるための質問。表層の要望ではなく**本質的な課題**に到達することを重視する。

### 背景 / 解く課題（Why-chain で深掘り）

- 「このプロダクトで解決したい**具体的な課題**は何ですか？（誰が・いつ・どこで困っていますか）」
- 「それはなぜ問題なのですか？」→ さらに「ではなぜそれが起きるのですか？」と**3段以上 Why を繰り返す**（5 Whys）。表層の要望の裏にある根本課題を特定する。
- 「その課題の**証拠・規模**はありますか？（発生頻度、所要時間、コスト、影響人数などの具体的な数値）」
- 「この課題を**解かずに放置したら何が起きますか？**（Cost of Inaction）」

### ターゲットユーザー / ペルソナ

- 「主に**誰のため**のプロダクトですか？1〜2の主要ペルソナに絞るとどうなりますか？」
- 「そのユーザーが片付けたい**仕事（Job）**は何ですか？どんな状況で発生しますか？」

### ステークホルダー / 決裁者

- 「この施策の**意思決定者（決裁者）**は誰ですか？」
- 「**影響を受ける関係者**は誰で、それぞれ何を気にしますか？（コスト、運用、セキュリティ等）」

### 現在の代替手段 / Workaround

- 「今この課題を**どうしのいでいますか？**（手作業、既存ツール、外部サービス、我慢）」
- 「その代替手段の**何が不十分**ですか？逆に、代替手段で十分なら本当に作る必要がありますか？」

### 価値提案 / 差別化 / Why now

- 「このプロダクトは**どのように**課題を解決し、代替手段より**何が優れて**いますか？」
- 「**なぜ今**作るのですか？（市場・組織・技術・コストの変化）」

### 成功指標（North Star / KPI / Guardrail）

- 「成功を**1つの指標（North Star）**で表すと何ですか？目標値は？」
- 「補助的に追う **KPI** は何ですか？それは**先行指標**（行動の早期シグナル）ですか、**遅行指標**（成果の確定値）ですか？」
- 「**悪化させてはいけない指標（Guardrail ＝失敗の許容ライン）**は？（例: 苦情件数、離脱率）」
- 「各指標は**どこで・どう計測**しますか？（取得元・自動/手動・頻度）。今すぐ取れない場合、**代理指標**で測れますか？」

### クリティカル制約 / 非ゴール

- 「守らないと成立しない**制約**は何ですか？（法規制、セキュリティ、予算、期限、既存連携）」
- 「このプロダクトが**明示的に目指さないこと（非ゴール）**は何ですか？スコープ外はどこですか？」

## 手順4: 実装済み機能一覧

> existing モードのみ。greenfield モードでは実装済み機能が存在しないため、この手順全体をスキップする。

### コード調査のヒントと提案

```bash
find src app lib -maxdepth 2 -type d 2>/dev/null
find . -type f -name "*Controller*" -o -name "*Service*" -o -name "*Component*" | head -n 20
```

提案例:

- 「`src/auth` ディレクトリが見つかりました。認証機能（ログイン、登録など）は実装済みですか？」
- 「`PaymentController` があります。決済機能は稼働していますか？」

### ヒアリング項目

- 「既に実装済みの機能はありますか？（提案した機能含む）」
  - **Category 1**（大分類: ユーザー管理、コンテンツなど）
  - **Category 2**（中分類: 認証、プロフィールなど）
  - **機能名**（ユーザー視点の名称）
  - **説明**（何ができるか）
  - **機能 ID**（FN-XXX 形式、連番）

## 手順5: Parking Lot（アイデア backlog）

`03-parking-lot.md` に、MVP に入れるか未確定のアイデアを集める。MVP の取捨選択は次スキル `/a-002a-slice-mvp-scope` が行うため、ここでは**優先度を厳密に決めず**幅広く拾う。

### 差分分析からの提案例

- 「Product Brief で『〇〇機能』への言及がありましたが、まだ実装されていないようです。Parking Lot に追加しますか？」
- 「現在の実装に『××』が含まれていますが、関連する『△△機能』は将来的に必要ですか？」

### ヒアリング項目

- **Category 1** / **Category 2**
- **機能名**（アイデア段階でも可）
- **説明**（目的や価値を中心に）

※ 機能 ID・優先度はこの段階では確定させず、柔軟性を重視して記載しない（優先順位付けは `02-mvp-scope.md` で行う）。

## 詳細な非機能要件について

初期フェーズでは、定量的な非機能要件（応答時間・稼働率・スケーラビリティ等）の詳細ヒアリングは行わない。MVP の作り方を変えるほど重要な制約のみを Product Brief の「クリティカル制約」に記載する（手順5 の「クリティカル制約 / 非ゴール」を参照）。詳細 NFR は設計フェーズ `/a-014-define-infrastructure` で扱う。

## 深掘りフレーム集（Product Brief / MVP Scope 共通）

表層の要望をそのまま機能化しないための思考技法。Product Brief（a-002）で課題・価値を掘り下げるとき、
および MVP Scope（`/a-002a-slice-mvp-scope`）で「本当に作るべきか」を判定するときに併用する。

### 5 Whys（最低3段）

根本課題に到達するため「なぜ？」を最低3段繰り返す。

- 「なぜそれが問題なのですか？」→「ではなぜそれが起きるのですか？」→ さらに「その背景にある原因は？」
- 表層の要望（解決策）と、その裏の根本課題（問題）を分けて記録する。
- 止め時: 「それ以上 why を遡っても自社で手を打てない」レベルまで来たら 1 つ上に戻る。

### Pre-mortem（事前検死）

リリース前に「すでに失敗した」と仮定し、原因を先回りで洗い出す。

- 「1年後、このプロダクトが**失敗に終わった**と想像してください。最も可能性の高い失敗原因は何ですか？」
- 「Day 1 で誰も使わなかったとしたら、理由は？（価値が伝わらない / 既存手段で足りる / 使うのが面倒 等）」
- 出てきた失敗要因を、Critical 制約・Core Scenarios の Critical Failure・Guardrail 指標に反映する。

### より安い代替手段 / 競合分析

「そもそも作らない」「もっと安く検証する」判断のため、既存手段と競合を必ず問う。

- 「今この課題を**どうしのいでいますか？**（手作業 / 既存ツール / 外部 SaaS / 我慢）。その代替手段の何が不十分ですか？」
- 「**手作業や既製ツールで MVP の仮説を検証できませんか？**（スプレッドシート / Slack / Zapier など）」
- 「同じ課題を解く**競合・類似プロダクト**はありますか？それらに対して何で勝ちますか（Why us）？」
- 代替手段で十分なら、その機能は Must にしない（→ Not Now / Won't）。

### Day 1 MVP の切り出し

価値提供が成立する最小の行動に絞り込む。

- 「**価値提供が成立する最小の利用者行動**は何ですか？（1〜3 ステップで言うと？）」
- 「その体験から**外しても価値が壊れない**要素はどれですか？」
- 「Day 1 に**必ず通ってほしい成功体験**を1〜3本に絞るとどれですか？」（→ Core Scenarios の Happy Path に対応）

### 1ヶ月後に検証したい仮説

MVP は仮説検証の手段。検証対象を 1〜3 個に絞る。

- 「このMVPで**検証したい仮説**は何ですか？『〜なら、ユーザーは〜する』の形で 1〜3 個に絞ると？」
- 「リリース1ヶ月後に**どの指標がどう動けば**『仮説は正しかった』と言えますか？」（→ North Star / KPI に対応）
- 仮説が 4 個以上に増えたら MVP が大きすぎる兆候。最も検証したい 1 つを選び直す。

### 絶対にやらないこと（Inversion）

「やること」ではなく「やらないこと」から考え、スコープ境界を明示する。

- 「このプロダクトが**絶対にやらないこと**は何ですか？（理由付きで）」
- 「**やると失敗する**ことは何ですか？（過剰な多機能化 / 全ユーザー対応 / 完璧な作り込み 等）」
- 「ここまではやらない、と**ステークホルダーと合意**できる境界はどこですか？」
- 結果は Product Brief の「非ゴール」、MVP Scope の Won't / Out of Scope に落とす。
